# Part A — Claim-to-code matrix (Sections 5–9)

Every technical claim of Sections 5–9 of the manuscript (`paper/latex/main.tex`), mapped to
the code in this repository that implements it and the test that exercises it. Paths are
relative to `reference_implementation/` unless they start with `reproducibility/`,
`paper/` or `compiled_engine/`. Code is cited by file and function (line numbers are not given, as they
change with edits). `main.tex:NNN` references point at the manuscript of 2026-10-29; the current `paper/latex/main.tex`
(revision of 2026-10-30/31) has moved some lines — search by the quoted text. Rows whose passage that
revision changed quote the current wording; rows whose claim it withdrew are kept, marked
**Withdrawn**, so that row and inconsistency IDs stay stable. Status vocabulary:

* **RUNNABLE** — a test, the reviewer example or the service-tier end-to-end run exercises it here;
* **INSPECTABLE** — source present (Go engine, configuration), not executable end to end here;
* **PARTIAL** — only part of the claim has a code counterpart in the package;
* **NOT IN PACKAGE** — no counterpart in the package (the notes say whether it is MISSING from
  the source snapshot or EXCLUDED by scope, per `reference_implementation/MAPPING.md`);
* **TEXT-ONLY** — a narrative or measured claim with no code counterpart possible.

A row's status says whether the *mechanism* can be inspected or run; whether the *number*
next to it can be regenerated is the subject of Part B. Every cited line
was re-read against the released files; inconsistencies between the paper's text and the
code are listed at the end of Part A rather than smoothed over.
